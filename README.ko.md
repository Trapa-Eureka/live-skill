# live-skills

문서·폴더·문서 묶음을 **검증된** [Agent Skills](https://agentskills.io)로 컴파일합니다. 템플릿 통과가 아니라 의미 수준의 품질 게이트가 그 검증을 뒷받침합니다.

**한 줄 포지셔닝:** *book-to-skill = 스냅샷, live-skills = 구독. 생성이 아니라 검증된 생성.*

[English README](README.md) · [License: MIT](LICENSE) · [npm](https://www.npmjs.com/package/live-skills) · [Changelog](CHANGELOG.md)

## 기능

- **문서를 Agent Skills로 컴파일.** 텍스트형 PDF, DOCX, Markdown/TXT, HTML(파일 하나, 폴더, 글롭)이 [Agent Skills](https://agentskills.io) 구조의 스킬 하나가 됩니다: `SKILL.md` 인덱스, 주제별 챕터 파일(모든 주장 뒤에 원문 앵커 `[§section-id]`), 그리고 챕터에서 모은 `glossary.md`·`patterns.md`·`cheatsheet.md`. 조립은 결정론이라 같은 입력과 같은 증류 결과는 항상 바이트 단위로 같은 파일을 만듭니다.
- **배포 전 품질 게이트.** 원문 섹션에서 골든 질문·답변을 만들고(각 문항은 원문 인용에 고정), 격리된 답변기가 **컴파일된 스킬 파일만으로**(에이전트가 스킬을 읽는 방식 그대로: 인덱스 → 챕터 하나) 답하고, 보수적인 채점기가 원문 기준으로 채점합니다. 통과율이 임계치(기본 0.9, 하한 0.5) 이상일 때만 배포되고, 실패한 스킬은 약한 챕터를 지목한 리포트와 함께 임시 디렉터리에 남습니다.
- **검증 가능한 산출물.** `manifest.json`에 원문 섹션 해시, 챕터 매핑, 골든 Q&A, 게이트 리포트, 산출 파일별 해시가 기록되어 `report`·`eval`이 오래되거나 변조된 스킬을 구분합니다.
- **`validate`·`report`·`eval`.** LLM 호출 없이 구조 검증, 마지막 게이트 리포트 출력, 기존 스킬 재채점(저장된 문항 또는 바뀐 원문 기준).
- **비용·안전 한계 내장.** 컴파일당 LLM 호출 상한(`MAX_LLM_CALLS`), 입력 크기 제한, 파서 타임아웃, 입력 토큰 상한. 초과하면 조용히 자르지 않고 분할을 안내하며 멈춥니다. 신뢰할 수 없는 텍스트는 프롬프트가 지시로 취급하지 않는 데이터 블록 안에서만 모델에 전달되고, 파일은 지정한 디렉터리 안에만 쓰며 기존 스킬은 `--force` 없이 덮어쓰지 않습니다.
- **문서의 언어로 말합니다.** 프롬프트가 제목·챕터·질문을 원문 언어로, 원문 용어 그대로 쓰도록 지시합니다.
- **기본은 Claude, 어디서나 모킹 가능.** LLM은 작은 provider 인터페이스 뒤에 있고, 테스트 스위트 전체가 네트워크 호출 0건의 대본형 목으로 돕니다.

## 왜 만들었나

문서를 [Agent Skills](https://agentskills.io)로 바꾸는 것은 이미 자리 잡은 분야입니다. 여러 도구가 기계적 변환(PDF/DOCX/Markdown/HTML → `SKILL.md` + 보조 파일)을 합니다. 그러나 조사한 도구 중 어느 것도 결과가 실제로 *맞는지*, 즉 컴파일된 스킬만 읽은 에이전트가 원문에 대한 진짜 질문에 답할 수 있는지 확인하지 않습니다.

live-skills 컴파일러는 **품질 게이트**를 중심으로 만들어졌습니다. 컴파일 뒤 원문 섹션에서 골든 질문·답변을 만들고, 각 질문에 *컴파일된 스킬 파일만으로*(에이전트가 읽는 방식 그대로: 인덱스 먼저, 그다음 해당 챕터) 답하게 하고, 원문 기준으로 채점해서 통과율이 임계치(기본 90%) 미만이면 배포를 거부합니다. 실패한 실행은 조용히 배포되지 않고, 어떤 챕터가 약한지 지목하는 리포트와 함께 임시 디렉터리에 기록됩니다.

## 구성 (v0.1)

| 층 | 하는 일 | 상태 |
|---|---|---|
| 컴파일 | 문서/폴더 → Agent Skills 표준 산출물(`SKILL.md` 인덱스 + 챕터 + 용어집 + 패턴 + 치트시트), 결정론 조립 | v0.1 |
| 품질 게이트 | 골든 Q&A 추출 → 격리된 답변 시뮬레이션 → 채점 → 통과/실패 임계치 | v0.1 |
| 자동 재컴파일 | 소스 워처 + manifest 해시 기반 증분 갱신("구독") | v0.2 (예정) |
| 이중 서빙 | 같은 산출물을 MCP 서버로도 서빙 | v0.3 (예정) |

지원 입력 형식: 텍스트형 PDF, DOCX, Markdown/TXT, HTML. 스캔/이미지 PDF(OCR)는 v0.1 범위 밖입니다.

Node.js 22.12 이상이 필요합니다(런타임 의존성이 요구하는 하한; CI는 22와 24에서 돕니다).

## 설치·사용

```bash
npm install -g live-skills            # 또는 npx live-skills <명령>
export ANTHROPIC_API_KEY=...          # 또는 작업 디렉터리의 .env 파일
live-skills compile ./manual.pdf --out ./my-skill   # 컴파일 + 품질 게이트
live-skills validate ./my-skill       # 구조 검증만(LLM 0회)
live-skills report ./my-skill         # 마지막 게이트 리포트 출력
live-skills eval ./my-skill           # 기존 스킬 재평가
```

npm 패키지명은 `live-skills`, GitHub 저장소는 `Trapa-Eureka/live-skill`입니다. LLM을 부르는 것은 `compile`·`eval`·스모크뿐이라 API 키도 그때만 필요합니다.

## 퀵스타트 (클론 기준)

```bash
npm install
cp .env.example .env              # ANTHROPIC_API_KEY 채우기
npm run cli -- compile ./samples/manual.pdf --out ./my-skill
npm run cli -- validate ./my-skill     # 구조 검증만(LLM 0회)
npm run cli -- report ./my-skill       # 마지막 게이트 리포트 출력
npm run cli -- eval ./my-skill         # 기존 스킬 재평가
```

`compile`은 품질 게이트를 통과할 때만 `--out`(기본값은 `~/.claude/skills/<slug>` 또는 `~/.agents/skills/<slug>`)에 스킬을 씁니다. 실패하면 대신 임시 디렉터리에 산출물을 보존하고 약한 챕터를 지목한 리포트를 함께 남깁니다.

## 실 LLM 스모크 (사람 전용, 비용 발생)

```bash
npm run smoke   # 실 Claude로 samples/manual.pdf를 컴파일하고 게이트 리포트 + 호출/토큰 비용 요약을 출력
```

그 밖의 모든 것(`npm run check` = typecheck + lint + test)은 대본형 목 LLM으로만 돕니다. 자동화 테스트에는 네트워크 호출이 0건입니다(`docs/TESTING.md`).

## 문서

`docs/`의 설계·스펙·태스크·검수 문서는 AI 페어링 워크플로(`docs/WORKFLOW.md`)로 개발한 1인 프로젝트의 작업 기록입니다. 전체 그림은 `docs/SPEC.md`(제품 스펙)와 `docs/DESIGN.md`(기술 설계, 날짜 붙은 결정 기록 포함)에서 시작하세요. 동작의 가장 정확한 참조는 코드 자체입니다. 영어 README는 [README.md](README.md)입니다.

## live-skills를 쓸 수 있는 분야

컴파일할 권리가 있는 텍스트라면 무엇이든 스킬이 될 수 있고, 게이트는 그 스킬이 원문을 얼마나 충실히 재현하는지 알려 줍니다. 아래 그룹을 펼치면 구체적인 예가 나옵니다. 공통 경계 두 가지: v0.1은 텍스트를 추출할 수 있는 소스만 읽고(OCR 없음), 게이트가 검증하는 것은 *당신의 문서*에 대한 충실도이지 문서 자체의 정확성이 아닙니다.

<details>
<summary><b>엔지니어링·개발자 문서</b> — API 레퍼런스, 아키텍처 기록, 런북</summary>

- SDK·API 레퍼런스: 코딩 에이전트가 문서에 적힌 정확한 파라미터 이름·기본값·한계로 답하게 합니다.
- 아키텍처 결정 기록(ADR)·설계 문서: 코드베이스의 "왜"를 그 출처 기록과 함께 에이전트에 줍니다.
- 런북·온콜 플레이북·사후 분석: 단계별 절차는 `patterns.md`에, 결정 규칙은 `cheatsheet.md`에 모입니다.
- 사내 코딩 표준·리뷰 체크리스트를 에이전트가 일관되게 적용합니다.
</details>

<details>
<summary><b>제조·현장 서비스·장비</b> — 매뉴얼, 정비 절차, 안전 지침</summary>

- 장비·기기 매뉴얼(동봉 샘플은 가상의 벤치탑 컨트롤러): 설치 한계, 교정 단계, LED·오류 코드 의미.
- 정비·수리 절차: "five seconds", "500 mA", 주소 범위처럼 바꿔 쓰인 값을 앵커 검사가 통과시키지 않습니다.
- 증류를 거쳐도 글자 그대로 살아남아야 하는 안전 지침·잠금 절차.
</details>

<details>
<summary><b>운영·표준 운영 절차(SOP)</b> — SOP 폴더, 온보딩, 체크리스트</summary>

- SOP 폴더를 팀 스킬 하나로 컴파일; 챕터별 리포트가 질문에 답하기엔 너무 빈약하게 적힌 절차를 보여 줍니다.
- 온보딩·직무 핸드북: 신입의 어시스턴트가 오래된 사본이 아니라 현재 정책으로 답합니다.
- 프로세스 체크리스트·승인 규칙이 `cheatsheet.md`의 즉답 규칙이 됩니다.
</details>

<details>
<summary><b>규제·컴플라이언스·정책</b> — 정책 묶음, 규정 PDF, 표준</summary>

- 사내 정책(보안, 데이터 취급, 경비)을 출처 조항으로 돌아가는 앵커와 함께 컴파일.
- 내부 재배포가 허용된 공개 규정·표준 묶음; 개정 추적은 v0.2 워처에서 예정.
- "어느 조항이 그렇게 말하는가"가 답만큼 중요한 감사·인증 요건.
</details>

<details>
<summary><b>고객 지원·제품 도움말</b> — 헬프 센터, FAQ, 문제 해결 가이드</summary>

- 헬프 센터 문서·FAQ: 지원 에이전트가 승인된 내용으로만 답하고, 게이트가 그것이 가능함을 증명합니다.
- 증상 → 조치 쌍이 절차·규칙이 되는 문제 해결 가이드.
- 자주 바뀌고 재컴파일 비용이 낮은 릴리스 노트·알려진 문제 목록.
</details>

<details>
<summary><b>교육·훈련</b> — 강의 자료, 교육 매뉴얼, 실험 프로토콜</summary>

- 직접 쓰거나 라이선스가 있는 강의 노트·교육 매뉴얼을 가르치는 절을 인용하는 튜터 스킬로.
- 골든 Q&A가 자료의 자가 점검 역할도 하는 실험실·워크숍 프로토콜.
- 모듈별로 컴파일한 자격증 학습 가이드; 게이트 리포트가 빈약한 모듈을 드러냅니다.
</details>

<details>
<summary><b>소상공인·지역 규정</b> — 세무 신고, 허가, 인허가</summary>

- 특정 관할의 신고 일정·허가 요건·수수료표를 소상공인 어시스턴트가 믿고 쓸 스킬로(이 엔진의 첫 콘텐츠 상품은 필리핀 사업 규정을 대상으로 계획).
- 같은 검증된 답이 필요한 여러 운영자에게 배포되는 프랜차이즈·공급사 매뉴얼.
</details>

<details>
<summary><b>오픈소스 프로젝트·개인 지식</b> — 프로젝트 문서, 연구 노트, 회의록</summary>

- 오픈소스 프로젝트의 심층 문서를 기여자 스킬로 컴파일; 문서가 바뀌어도 게이트가 정직함을 지킵니다.
- 직접 쓴 연구 노트·독서 요약·회의록을 앵커를 잃지 않고 질의 가능하게.
</details>
